# 2026-09-28

## 修复：图集详情页主图被放大，需缩放 67% 才能看全

- 原因：`gallery-detail.html` / `gallery-detail2.html` 用 `<style type="text/tailwindcss">@import "gallery-detail.css";</style>` 引入样式，本地 file:// 打开时该 @import 常加载失败 → CSS 全部失效，主图按原始像素尺寸铺开；同时 `.portrait-container` 写死 `aspect-ratio: 3/4` 竖版比例，横图被压缩。
- 改动：
  - `gallery-detail.css`：容器改为 `height:auto` 去掉 3:4 固定比例；图片 `width/height:auto + max-width:100% + max-height:calc(100vh - 230px) + object-fit:contain`；新增全屏 lightbox 样式；缩略图栏高度同步。
  - 两个 HTML：样式改用原生 `<link rel="stylesheet">` + 内联兜底 `<style>`（不依赖 Tailwind 编译），新增 `#lightbox` DOM 与点击主图全屏预览、Esc/点背景关闭。
  - `gallery_generator.py`：模板同步以上修改（f-string 中 CSS 花括号需 `{{ }}` 转义），避免下次生成回退。
- 约定：后续该项目页面涉及自定义样式，优先用原生 `<link>`/`<style>`，不要用 `type="text/tailwindcss"` + @import。

## 修复：音乐改版后播放按钮点了没反应（真凶是 lucide CDN，不是样式）

- 现象：方形卡片改完后点播放无任何反应，控制台无显式报错（play 的 rejection 被 `.catch(()=>{})` 吞掉）。
- 排查：无头 Edge + 自造测试页把状态回传到本地 server 日志（`fetch('/__result?d='+JSON)`），对比 `lucide/readyState/networkState/isPlayingClass`。
  - 修复前回传：`lucide:"undefined"`、`networkState:1`（没发起加载）、`readyState:0`、`isPlayingClass:false`。
  - 修复后回传：`lucide:"object"`、`paused:false`、`readyState:4`、`duration:173.56`、`isPlayingClass:true`。
- 根因：`https://cdn.jsdelivr.net/npm/lucide@latest` 现在解析到 **CJS** 版 `dist/cjs/lucide.js`（v1.48.0），浏览器里不挂 `window.lucide`；`script.js` 第 1 行 `lucide.createIcons()` 抛 ReferenceError → 整个 script.js 后续代码全部不执行 → 播放事件没绑上。改用原生 `controls` 时不依赖 JS，所以之前一直没暴露。
- 改动：
  - 全部 7 个 HTML 的 lucide 引链改为 `https://cdn.jsdelivr.net/npm/lucide@latest/dist/umd/lucide.min.js`（UMD 会挂 `globalThis.lucide`，已 curl 验证 200）。
  - `script.js` 顶部加 try/catch + `typeof lucide !== 'undefined'` 保护，图标再挂也不能拖垮其它逻辑。
  - 音乐播放补健壮性：`play()` 的 rejection 打印 console.error 并置 `is-error`；新增 `error`/`waiting`/`playing`/`loadedmetadata` 监听；卡片显示「加载失败 / 播放失败」，`is-loading` 时封面图标半透。
  - 首卡 `preload="none"` → `preload="metadata"`，加载后直接显示总时长。
- 排查套路（可复用）：本机无 Chrome，用 `/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge --headless=new --disable-gpu --no-sandbox --mute-audio --autoplay-policy=no-user-gesture-required --virtual-time-budget=25000 --dump-dom <url>`；页面用 fetch 把调试结果打到 python http.server 日志里读取（后台起服务要用 run_in_background，否则命令结束就被杀）。

## 改版：视频作品模块 横屏 16:9 → 竖屏 3:4

- 需求：视频全是 3:4 竖屏，但引用 B站 iframe，担心播放器强制横屏。
- 事实确认：`GET api.bilibili.com/x/web-interface/view?bvid=BV1JMeY61EfZ` → `dimension {width:720, height:960, rotate:0}`，确为 3:4；无头 Edge 直接以 400×533（3:4）视口打开 `player.bilibili.com/player.html?...` 截图，画面完整铺满无黑边 → **B站外链播放器自适应容器，容器比例由页面控制**。
- 改动：
  - `style.css` 新增 `.video-frame`（`aspect-ratio:3/4` + 黑底 + iframe 绝对定位铺满）、`.video-frame--wide`（16:9 兜底，将来有横屏素材时给卡片加这个类）、`.video-placeholder`（无源占位，同 3:4）。
  - `video.html`、`index.html`：iframe 容器 `aspect-video` → `.video-frame`，各 8 处占位 → `.video-placeholder`；iframe 加 `loading="lazy"`、去掉 w-full/h-full 类。
  - `video.html`、`gallery.html` 头部补 `<link rel="stylesheet" href="style.css">`（截图发现 video.html 的 tailwind `@import` 在无头环境下没编译，`.video-frame` 失效、iframe 塌成默认 300×150——再次验证必须用原生 link）。
- 注意：无头截图里 iframe 内 B站播放器是纯黑（播放器 JS 在 virtual-time 下没跑完），真实浏览器正常；判断 iframe 内部效果要直接对 player.bilibili.com 的 URL 截图。
